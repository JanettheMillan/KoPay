# Documentación de KoPay

Este directorio reúne el alcance, diseño, planificación, historias, pruebas y evidencias previstas para desarrollar KoPay en el repositorio de entrega. Un caso escrito no equivale a una prueba ejecutada ni una tarea propuesta equivale a un avance realizado.

## Orden de lectura

1. [Plan del proyecto](plan-del-proyecto.md): producto completo, alcance, calendario y entregables.
2. [Backlog de desarrollo](backlog-desarrollo-desde-cero.md) y [cronograma](cronograma-y-trazabilidad.md): 97 actividades de cinco sprints, desde la base Flutter hasta la vista de contador y el APK.
3. [Arquitectura](arquitectura.md): módulos, flujo de datos, persistencia y patrones propuestos.
4. [Historias de usuario](historias-de-usuario.md): necesidades, criterios de aceptación, sprint, actividades y responsables propuestos.
5. [Plan de pruebas](plan-de-pruebas.md): casos unitarios, de interfaz e integración, más registro de ejecución.
6. [Guía de evidencias](guia-de-evidencias.md): cómo guardar pruebas, capturas, tablero y cambios de Git sin confundir planificación con resultados.

## Destino de entrega indicado por el equipo

- Repositorio: [JanettheMillan/KoPay](https://github.com/JanettheMillan/KoPay).
- Tablero: [KoPay Project 3](https://github.com/users/JanettheMillan/projects/3).

Las 97 actividades planificadas tienen Issues asignados y aparecen en el Project; el [backlog](backlog-desarrollo-desde-cero.md) enlaza cada una. El tablero registra el avance real y sustituye las copias de estado fechadas. Una tarjeta creada no acredita trabajo realizado.

## Estado documental

Los documentos describen el trabajo previsto para construir la aplicación por módulos en el repositorio de entrega. Los responsables, fechas y criterios pueden ajustarse en el Project mediante acuerdos del equipo. Los resultados de implementación, pruebas, despliegue y APK se registrarán únicamente cuando se hayan realizado y cuenten con evidencia.
